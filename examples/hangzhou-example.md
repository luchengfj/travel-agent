## 模式一 · deal（比价）

### 用户输入
> 杭州这几家杭帮菜到底哪家值？人均差得有点离谱。

### 合格输出骨架

首行模式标签 + 一句结论：

```
【比价】查了 14 家，人均从 ¥18（新丰小吃）到 ¥147（楼外楼），均值 ¥80。
真正拉开差距的不是「好不好吃」，是「店的位置」——景区店比市区同名店贵 1.5–2 倍。
```

**KPI 三连**（必须三个，不是一个）：

| 项 | 值 |
|---|---|
| 最贵 | 楼外楼(孤山路店) ¥147/人 |
| 最便宜 | 新丰小吃(庆春路店) ¥18/人 |
| 全员均值 | ¥80/人（14 家） |

**降序条形榜**（14 家长条，右侧标金额）：

```

绿茶(龙井船宴)     ¥88   ████████████
老头儿油爆虾       ¥86   ███████████
```

**两块结论**：
- 最省：新丰 ¥18 × 2 = ¥36 / 顿（早餐）；午餐菊英 ¥31 × 2 = ¥62
- 最贵：楼外楼 ¥147 × 2 = ¥294 / 顿，等于 4 顿新白鹿

**口径声明**（必须有）：金额为携程「来自用户反馈」的历史人均，非当日菜单价，实际波动 ±20%。

### 检查点
- [ ] 有 3 个 KPI，不是只报一个「均值」
- [ ] 条形榜按降序，条长与金额成比例
- [ ] 说清「贵的成因」而非只排名
- [ ] 给了最省/最贵组合的**总额（×2 人）**
- [ ] 声明了数据口径与误差

## 模式二 · prep（行前准备）

### 用户输入
> 下周三出发去杭州，这几天要准备啥？

### 合格输出骨架

**倒计时条**（按截止日倒排，最关键那条单独高亮）：

```
今天 11/3（周一）        距出发 5 天
⚠️ 11/3 08:00 — 灵隐寺香花券开抢（每日限量，节假日 3 分钟售罄）
```

**按截止日分组**（**每组内日期必须单调，不许跨组倒挂**）：

| 截止 | 事项 | 怎么弄 |
|---|---|---|
| **11/3 前** | 灵隐寺香花券（¥30/人） | 「灵隐寺」公众号预约，选 11/9 上午场 |
| 11/3 前 | 西湖游船船票 | 携程/现场均可，非节假日不紧张 |
| **11/6 前** | 高铁票（深圳北→杭州东） | 12306 提前 5 天，选 07:00–09:00 班次 |
| 11/6 前 | 酒店（西湖东侧） | 携程搜「湖滨」区域，确认有空调制热 |
| **11/8 前** | 打包 | 见下方清单，洋葱式叠穿 |
| **落地当天** | 机场/车站→酒店交通 | 机场大巴 20 元或地铁，**不要提前买**，看航班落地时间再定 |

**打包清单**（勾选式，不多于 12 项）：防风外套 / 薄羽绒 / 舒适鞋（日均 1.5 万步）/ 雨伞 / 充电宝 / 身份证 / 常用药 / 保温杯 …

**尾注**：⚠️ 抢票类事项失败要有 Plan B（灵隐寺未约到 → 改法喜寺，人少且免费）

### 检查点
- [ ] 有倒计时/日期锚点，不是「出发前记得」
- [ ] 按截止日分组，**组内日期不倒挂**（历史翻车点 #4）
- [ ] 抢票项有 Plan B
- [ ] 落地交通写明「不要提前买」这类反直觉建议

## 模式三 · ontrip（在途）

### 用户输入
> 到杭州了，今天下雨，原定去灵隐寺还去吗？

### 合格输出骨架

**首行给结论**（不是先讲天气）：

```
【在途】建议改期——今天中雨、灵隐寺 90% 步道露天，改明天上午（明天多云）。
今天换「室内 + 短距离」组合。
```

**场景替代卡**（4 张，每张=一个可执行方案）：

| 原计划 | 今天改 | 理由 | 交通 |
|---|---|---|---|
| 灵隐寺 | 浙江省博物馆(孤山馆) | 免费、室内、2 小时逛完 | 打车 15 分钟 |
| 飞来峰 | 中国丝绸博物馆 | 室内、有互动展 | 打车 20 分钟 |

### 检查点
- [ ] 首行是结论（去/不去/改哪），不是天气播报
- [ ] 每个替代方案给「交通方式 + 耗时」
- [ ] 电话是现役号码，且主动标注已废止的
- [ ] 有情绪价值判断（「雨中看湖反而出片」）

## 模式四 · review（复盘）

### 用户输入
> 回来了，帮我看看这次超支没有。

### 合格输出骨架

**三数字并排**：

| 实际总支出 | 超支 | 单项占比 |
|---|---|---|
| **¥3286** | **+¥142（+4.5%）** | 餐饮 46% |

**对账表**（超红 / 省绿 / 平灰）：

| 项目 | 预算 | 实付 | 差额 |
|---|---|---|---|
| 交通 | 1320 | 1420 | **+100** 🔴 |
| 餐饮 | 1428 | 1512 | **+84** 🔴 |
| 门票 | 190 | 190 | 0 ⚪ |
| 住宿 | 206 | 164 | **−42** 🟢 |
| **合计** | **3144** | **3286** | **+142** |

**左右两块结论**：
- **超支来源**：交通 +100（返程改签高铁，原班次误点）；餐饮 +84（楼外楼一顿 ¥294，比预算高 ¥80）
- **省下的**：住宿 −42（提前订到 ¥82/间，预算按 ¥103 估）

**下次改进清单**（编号 + 金额佐证，不许空话）：
```
01 返程票买「可改签」档，多 ¥20 但省 ¥100 改签费
02 楼外楼这类 ¥147 的店，一顿就够，别排两顿
03 住宿提前 14 天订，实测比提前 3 天便宜 ¥21/间/晚
04 餐饮预算按「人均 ¥65 × 顿数」估，这次低估了 8%
05 门票预留 ¥50 弹性（临时加的游船）
```

**尾注**：⚠️ 记账要趁早，隔三天就记不清哪笔是哪笔了。

### 检查点
- [ ] 三个数字齐全（总额/超支/占比）
- [ ] 对账表四列且有颜色区分
- [ ] **区分「不可控超支」和「主动消费超支」**（改签是被动、楼外楼是主动）
- [ ] 改进清单每条带金额，不是「下次注意」
- [ ] 合计 = 分项加总（`1320+1428+190+206=3144`；`1420+1512+190+164=3286`）

## 历史翻车点（本样例相关）

1. **旧比价卡印「均值 ¥77.37」，正确值是 ¥80.14** —— 14 家加总 1122÷14=80.14。
   原因：早期手算漏了一家或重复计。**这就是为什么必须用脚本验算。**
2. prep 卡把「机场大巴(11/9 查)」塞进「11/3 前」组 —— 组内日期倒挂。
3. 给 12301 / 12318 当旅游热线 —— 2021 年底已并入 12345。
4. 复盘只报总超支，不分「不可控 vs 主动」—— 结论会误导人下次怎么改。
5. 替代方案只写「换个地方」不给交通耗时 —— 用户当场没法决策。
