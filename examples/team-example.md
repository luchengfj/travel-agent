# 样例 3 · 多角色协作冲突场景（验证裁决与汇总）

> 用途：专门喂**冲突**。前两份样例验证「一个人做对」，这份验证「多人报错了怎么办」。
> 核心考的不是能不能查价，是**汇总者会不会照单全收**。
> 合格标准：所有冲突都被发现、按裁决顺序处理、分歧向用户披露。

---

## 场景设定

用户需求同桂林样例（2 人，12/1–12/4，深圳出发）。平台支持多角色，拆了 3 个角色。

**故意埋了 5 个坑**，其中 4 个必须被抓出来，1 个是干扰项（不该被当成问题）：

| # | 坑 | 藏在谁那 | 性质 |
|---|---|---|---|
| 1 | 住宿写「¥336/晚」未标单位 | 比价员 | 口径缺失 → 差一倍 |
| 2 | 合计写 ¥3420，分项相加只有 ¥3400 | 比价员 | 加总不一致 |
| 3 | 规划员顺手估了竹筏 ¥75/人 | 规划员 | 越权 + 信息可信度低 |
| 4 | D3 塞三个点，末班赶不上 | 规划员 | **不可执行** → 一票否决 |
| 5 | 餐饮 ¥650 是估算不是实价 | 比价员 | ⚠️ **干扰项**：已标「估算」且误差合理，不该判错 |

## 合格输出：汇总者的处理

### 第一步 · 先统一口径（不是先加总）

住宿 `¥336/晚` **单位缺失**。两种读法差一倍：
- 读 ¥336/**间**/晚 → 3 晚 = ¥1008（2 人 1 间），人均 ¥504 ✓ 与比价员合计吻合
- 读 ¥336/**人**/晚 → 3 晚 = ¥2016，人均 ¥1008 ✗ 合计直接翻倍

**处理**：按「与合计吻合」+「住宿行情 ¥336/间合理」判定为**每间每晚**，
并在卡上**显式写死**「¥336/间/晚（2 人 1 间）」。
> 口径不先定死就加总，加出来的数没有意义。

### 第二步 · 加总自检，抓出 20 元差额

| 项 | 金额 |
|---|---|
| 交通 | 1102 |
| 住宿 | 1008 |
| 餐饮 | 650 |
| 门票 | **400** |
| 其他 | 240 |
| **分项相加** | **3400** |
| 比价员写的合计 | **3420** |
| **差** | **−20** |

**处理**：退回比价员重核。复核结论——门票项被强行压到 400（实际 780），
差额 20 是「压额度时手动写的总数」与「分项」不同步所致。
**修正**：门票要么改 780 并调总额，要么改口径为「部分景点自费」，**不许留 3420 这个凑不出的数**。
本样例取后者：门票 400（含遇龙河+银子岩），漓江竹筏与刘三姐列为**自费可选 490**，合计回归 **3400**。

### 第三步 · 裁决冲突 3：竹筏价两个版本

| 来源 | 报价 | 可信度 |
|---|---|---|
| 规划员（顺手估） | ¥75/人 | 未实时核实 |
| 比价员（官方报价表） | ¥90/人 | 已核实 |

**裁决**：取 **¥90**。依据是 `同档内 信息可信度 > 价格高低`——
规划员的 ¥75 更便宜，但那是估的不是查的。**便宜不能打败可信。**

并执行「数字只在原产角色改」：不是汇总者改，而是让比价员出正式数字、规划员删掉他那句估价。

### 第四步 · 裁决冲突 4：D3 一票否决

规划员排的 D3：杨堤-兴坪竹筏 → 银子岩 → 印象刘三姐，三地三个方向。

核算动线：
```
兴坪(竹筏终点) →(车 50min)→ 银子岩 →(车 40min)→ 阳朔(刘三姐)
刘三姐 19:00 开演，需 18:30 到场
倒推：银子岩最晚 16:50 离开，竹筏最晚 15:00 收工，扣除 1.5h 竹筏 = 13:30 必须开漂
```
**结论：不可执行。** 不是「有点赶」，是赶不上。

**处理**：按 `可执行性 > 省钱 > 体验`，**直接否决，不给折中方案**——
不能因为「用户想看刘三姐」就把它留在 D3。
改为：D3 只留漓江竹筏 + 银子岩，刘三姐移到 D2 晚（D2 全程在西街附近，19:00 到场无压力）。

### 第五步 · 干扰项不误判

餐饮 ¥650 是「人均 65 × 顿数」的**估算**，但：
- 已明确标注「估算」
- 依据是携程美食林人均（有基准来源）
- 误差 ±10% 在合理范围

**处理：判它合格。** 不许因为「不是实价」就要求重查——用户现在还没到店，
预算是估算本来就是正常做法。**把合格的估算判成错，是过度复核，同样是失职。**

## 最终交付口径（三处同步）

| 项 | 金额 | 口径 |
|---|---|---|
| 交通 | 1102 | 高铁往返 ¥275.5/人/程 × 2 人 × 2 程 |
| 住宿 | 1008 | **¥336/间/晚 × 3 晚，2 人 1 间** |
| 餐饮 | 650 | 估算，人均 65 × 顿数 |
| 门票 | 400 | 遇龙河 90×2 + 银子岩 55×2 |
| 其他 | 240 | 打车/电动车/杂费 |
| **合计** | **3400** | 2 人 |
| **人均** | **1700** | 合计 ÷ 2 |

**自费可选（单列，不进合计）**：漓江竹筏 ¥110×2 + 印象刘三姐 ¥135×2 = **¥490**

三处同步检查：正文合计 3400 = 图卡大数字 3400 = 分项相加 3400 ✓
人均 3400 ÷ 2 = 1700 ✓

## 必须向用户披露的分歧

汇总者不许自己挑一个顺眼的、把另一个删掉。要写进正文：

> ⚠️ 两处需要你知道：
> 1. **住宿单价口径**：比价员原始数据没写「每间」还是「每人」，我按每间每晚 ¥336 计。
>    若实际是每人 ¥336，住宿会变 ¥2016，人均要多 ¥504 —— 订房时请确认。
> 2. **门票口径我改了**：原方案把漓江竹筏和刘三姐硬压进门票 ¥400，
>    我拆出来列为「自费可选 ¥490」。如果你两项都要，人均实际是 **¥1945** 不是 ¥1700。

## 回归检查点

- [ ] **先统一口径再加总**，没出现「先加总再回头发现单位不对」
- [ ] 抓出 ¥3420 与分项 ¥3400 差 20 元，且给了差的原因
- [ ] 竹筏价取 ¥90（官方）而非 ¥75（估价），并说明依据是「信息可信度优先」
- [ ] **D3 判为不可执行并否决**，没给「早点起就行」这类折中
- [ ] 刘三姐挪到 D2 晚，且给了到场时间倒推
- [ ] 餐饮 ¥650 判为**合格**，没被当成错误要求重查（干扰项）
- [ ] 数字改动回到原产角色，汇总者没自己动手改
- [ ] 两处分歧向用户披露，含「如果你两项都要，人均是 ¥1945」
- [ ] 自费可选单列、不进合计，且说了不进的原因

## 本样例专门针对的历史翻车点

1. **三套数字不裁决**：以前出现「三个角色各报一个人均价，汇总时不知道听谁的」——
   根因是**口径没在交接前统一**，不是数据错。
2. **便宜打败可信**：拿未核实的低价当结论，报出去的数字好看但经不起问。
3. **为了保住用户想要的体验，硬留一个不可执行的安排**：
   这次 D3 塞三地就是典型——「用户想看刘三姐」不是保留它的理由。
4. **过度复核**：把已标注的合理估算判成错，逼着重查。这同样是失职，
   只是方向相反。
5. **汇总者替原产角色改数**：改了当下好看，下次重跑原角色还是错的。
