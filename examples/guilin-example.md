# 回归基准样例 · 桂林阳朔 4 天 3 晚（深圳出发）

> **用途**：改动 `travel-agent.md` 后，用本样例对照跑一遍，逐项打勾「回归检查点」，看行为有没有退化。
> **原始输入**（用户原话，m01046）：「我需要一个广西3天游，12。1-12.4日回来的旅游，深圳出发」
> **后续回答**（m01058/m01062）：「A（桂林阳朔）」「山水暴走 + 美食混合」，人数预算未回 → 默认 2 人 / 人均 1500。
> **基准日期**：2026-11-01
> **模型能力假设**：无图像输入（走「渲染后自检」B 路径）
> **等价输入复现**：把「原始输入 + 后续回答」按顺序喂给 Agent，输出应逐项命中下方检查点。

## 第 1 轮 · 首轮提问（plan 模式）

```
(当前：plan) 一句话结论：先确认 3 件事，12/1–12/4 其实是 4 天 3 晚，不是 3 天。

我是「行旅」，你的旅行规划与随行管家——负责让这趟广西行可执行、可预算、可兜底。

动手前先对齐 3 个关键项（都给默认值，不确定就说「按你的来」）：

1. 去哪一块广西？
   A. 桂林+阳朔（山水经典，高铁直达阳朔）← 默认
   B. 北海+涠洲岛（看海，需飞或长高铁）
   C. 南宁+德天瀑布（边境瀑布线）
2. 几个人、人均预算多少？（默认：2 人，人均 ¥1500，含往返大交通）
3. 想要的节奏？（默认：山水暴走 + 美食混合）
```

**命中要点**：首行标模式；自我介绍在正文首句；只问 3 个；每问带默认值；主动指出「4 天 3 晚」。

```
- 偏好：山水暴走 + 美食混合

```

**命中要点**：`需求锁定` 6 项结构化；**星期几是用工具/脚本验算的，不是心算**。

## 第 5 轮 · 预算明细（价格口径示范 · 重点看这节）

> 口径声明：住宿一律 **¥/间/晚**；餐饮一律 **人均**；合计一律 **2 人**。
> 说明：第 4 轮逐日表只列**重点餐**（示意吃什么），**餐饮与市内交通的总额以本预算表为准**，逐日表不参与加总。

| 项目 | 单价口径 | 计算 | 2人合计 | 人均 |
|---|---|---|---|---|
| 高铁往返 | ¥275.5/人/单程 | 275.5 × 2 人 × 2 程 | ¥1102 | ¥551 |
| 住宿 3 晚 | ¥336/间/晚 | 336 × 3 晚 × 1 间 | ¥1008 | ¥504 |
| 餐饮 8 顿 | 2 人合计 | 按 8 顿估（4 重点餐 + 简餐/早餐），合计 ¥650 | ¥650 | ¥325 |
| 门票 | 单项挂牌 | 遇龙河90 + 漓江110 = 200/人 | ¥400 | ¥200 |
| 市内交通 | 2 人合计 | D1 站→西街打车80 + D2 包车半天100（含十里画廊电动车） + D3 西街→杨堤60 = 240 | ¥240 | ¥120 |
| **合计** | | | **¥3400** | **¥1700** |

**加总自检**：1102 + 1008 + 650 + 400 + 240 = **3400**（2 人）；÷2 = **1700**（人均）✓
**人均分项核对**：551 + 504 + 325 + 200 + 120 = **1700** ✓
**餐饮口径核对**：4 顿重点餐人均 75+81+61+30 = 247，2 人 ≈ 494；其余简餐/早晚餐合计 ≈ 156；494 + 156 = **¥650**，与预算表一致 ✓
**三处同步**：正文人均 1700 = 图卡大数字 1700 = 分项加总 1700 ✓
**起价提示**：若查到的 ¥290/间 是「起价」，按 `290 × 1.25 ≈ ¥363` 做预算，需重算住宿。

**命中要点**：住宿写「¥/间/晚」并 ÷2 换算人均（不再出现 ¥168/人 与 ¥336/间 混用）；一个口径；加总自检；起价×1.25。

## 已知的历史翻车点（本样例就是要防这些）

1. 把「12/1–12/4」当成 3 天 → 行程与预算全错位。
2. 住宿把 ¥336/间 误写成 ¥168/人，导致整卡金额错一倍。
3. 纯 AI 生图做数据卡 → 「1572」糊成「1527」，数字不可读。
4. prep 卡把「11/9 查」塞进「11/3 前」组 → 组内截止日期自相矛盾。
5. 给 12301 当旅游热线 → 已是空号。
6. 把 10 天后的天气当真预报给 → 实际 API 只有 7 天。
7. 编辑后未确认高度变化就发图 → 改动没生效也看不出来。
