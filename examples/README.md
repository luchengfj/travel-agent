这个目录放的是**提示词的验收样例**。改完 `C:\ai\travel-agent.md` 之后，用它们跑一遍，
确认 Agent 的行为没退化。不是给人看的示例输出，是**给下一次改提示词的自己看的对照表**。

## 一键静态回归（先跑这个）

`regress.py` **不调大模型、不渲染图片**，只做三件确定性的事，一条命令出对比报告：

```bash
PY="C:/Users/cheng/.dsh/dsh-runtimes/dsh-next-primary-runtime/dependencies/python/python.exe"
cd C:/ai && PYTHONIOENCODING=utf-8 "$PY" examples/regress.py
# 落盘报告：  ... examples/regress.py --report
# 只打印「该喂什么给 Agent」： ... examples/regress.py --emit-prompt
```

- **退出码 0 = 全绿，1 = 有 FAIL**（可直接接 CI / git hook）。
- 检查 [A] `travel-agent.md` 结构：20 个一级章节、7 张图卡规格、21 条硬规则关键词、出境卡 5 项附加块。
- 检查 [B] **算术重算**：四份样例的分项→合计→人均全部用 Python 重算一遍，
  外加 THB→CNY 取整换算；基准文档里印错的数字（如 4520 / 9205 / 2950）会被抓出来。
- 检查 [C] 基准完整性：行数 / 检查点条数 / 正确值锚点 / bug 记录区是否还在，
  **以及干净交付物（桂林卡 HTML、提示词本身）里已修 bug 是否复发**。

### 一个踩过的坑（别改回去）

首版把「错值不得出现」做成对**基准文件全文**的检查，一口气报了 5 个假 FAIL：
基准样例的职责本来就是**记录**这些 bug（历史翻车点、回归检查点、角色原始交付里
都写着 `¥168/人`、`¥77.37`、竹筏 `¥75`……）。所以脚本现在分两类文件：

- **基准样例** → 只断言「**正确值必须出现**」（`FACTS`）+「bug 记录区必须还在」（`DOC_RECORD_SECTIONS`）；
- **干净交付物**（`cardtest/guilin.html`、`travel-agent.md`）→ 才做「错值缺席 / 修复项在场 / 出现次数下限」。

另注 `travel-agent.md` 里 `¥168/人` 是**故意的反例说明**，提示词的缺席清单绝不能放这条。

### 脚本查不了的四项（仍要走下面的人工流程）

1. 逐轮**行为输出**是否同构（首行模式标签、≤3 问带默认值、三档内容不同……）
2. 图卡是否真的渲染、尺寸是否正确、有视觉能力时是否逐字目检 kicker / 页脚
3. 实时数据是否现查（登录态房价、天气窗口、12345 现役号码）
4. 措辞差异 ≠ 退化；但硬事实（票价/汇率/政策日）与口径一旦不同就必须判退化

## 怎么跑一次回归（人工逐轮对照）

1. **读基准**：打开对应 `*-example.md`，只看「第 1 轮」里的**用户输入**部分。
2. **喂给 Agent**：把该输入原样发给待测的 Agent（同一个 `travel-agent.md`）；若样例有后续回合，
   按顺序把用户的简短回答（如「A」「继续」）依次发过去。
3. **逐轮对照**：把 Agent 的实际输出，和基准里对应轮次的「外壳 + 结构 + 关键数字」对照。
   不需要字字相同，但**结构、口径、结论必须同构**。
4. **打勾**：用文件末尾的「回归检查点」清单逐项判定。任一项 ✗ = 那次改动引入了退化。
5. **记录**：在下方「回归记录」表里加一行，写明日期、改了什么、哪些检查点没过。

## 判定标准（重要）

对照时看**四类东西**，按严格程度从高到低：

| 类别 | 判法 | 例子 |
|---|---|---|
| **硬事实** | 必须完全一致，错一个就是 bug | 高铁 ¥275.5/人；住宿 ¥336/间/晚；12301 已并入 12345 |
| **口径** | 必须同一口径、且显式声明 | 住宿写「¥/间/晚」不写「¥/人」；一个口径贯穿全卡 |
| **结构** | 章节齐全、顺序对、该有的块不缺 | deal 卡有 3 个 KPI + 降序条形榜；prep 卡按截止日分组 |
| **文风** | 只要不违背「沟通纪律」即可，允许措辞不同 | 首行有模式标签；一次 ≤3 问；先结论后展开 |

**不要把「措辞不同」判成退化。** 提示词管的是行为约束，不是逐字复读。
反过来，**硬事实和口径不同必须判退化**——这两类是我们真踩过坑的地方。

## 数字自检（写基准时最容易出错的地方）

基准文件本身也会算错，而**基准算错等于白做**。所以两个样例都内置了加总自检行。
修改样例如下任何数字后，必须重跑一遍：

```bash
# 用运行时自带 Python 验算（bash 里 python 不在 PATH）
PY="C:/Users/cheng/.dsh/dsh-runtimes/dsh-next-primary-runtime/dependencies/python/python.exe"
"$PY" -c "print(275.5*2*2 + 336*3 + 650 + 200*2 + 240)"   # 桂林：应输出 3400
```

铁律：**分项相加 = 合计；2 人合计 ÷ 2 = 人均；图上大数字 = 正文数字。**
三处任一不一致，就是 `travel-agent.md` 里「价格口径铁律」那节没落实。

## 已沉淀的历史翻车点（两个样例末尾都有，改提示词时先看这个）

1. 「12/1–12/4」当成 3 天 → 行程与预算全错位
2. 住宿 ¥336/间 误写成 ¥168/人 → 整卡金额错一倍
3. AI 生图做数据卡 → 「1572」糊成「1527」

6. 把 10 天后的天气当真预报 → 天气 API 只有 7–16 天
7. 编辑后没确认高度变化就发图 → 改动没生效也看不出来

## 只有「读图自检」才抓得到的 bug（2026-11-03 实测）

换到有视觉能力的模型后，把桂林卡读回来做了一轮像素级检查，**一次抓出 4 个 bug**。
这些 bug 在 B 路径（无视觉能力）下**全部抓不到**——尺寸校验和 grep 数 DOM 块都查不出来，
因为 HTML 结构是完整的，错的是字面内容和跨区块的数字一致性。

| # | Bug | 为什么只能靠看图 | 教训 |
|---|---|---|---|
| 1 | 顶部英文写 `3 DAYS 3 NIGHTS`，实际是 4 天 3 晚 | 英文小字在 kicker 里，且中文副标题写对了，grep 中文查不出 | **翻车点 #1 是规则，我写下了照样踩**。规则必须配「渲染后逐字看页眉页脚」的检查动作 |
| 2 | 均衡档门票 ¥255，逐日行程实际 ¥260 | 两个数字在不同区块，各自都「合理」 | 卡片内部也要做加总自检，不能只查「正文 vs 图卡大数字」 |
| 3 | D4 返程标「—」，写「已计入交通」，但 D1 只计了去程 | 逐日相加时才发现交通只算出 ¥551（应为 ¥1102） | **「已计入」是最危险的四个字**，它让缺失看起来合理。凡写「已含/已计入」，必须指明含在哪一项、金额是多少 |
| 4 | 预算表「其他 ¥60」，样例口径是「市内交通 ¥120」 | 分项名称和金额都和基线不一致 | 改金额时只盯了总数 1700 对不对，没管构成 |

**结论**：B 路径（无视觉）的自检是「防呆不防错」——能挡住「编辑没生效」这类问题，
挡不住「字面错、区块间对不上」。所以提示词里那句「无视觉能力时必须声明『未做像素级目检』」
是必须保留的：**看不清就不能假装看清了。**

修复后：门票 200（遇龙河 90 + 漓江 110）、市内交通 120，银子岩改为「可选自费 ¥55/人」不进均衡档，
`551 + 504 + 325 + 200 + 120 = 1700` ✓，卡高 6754 → 6922（确认改动生效）。

## 境外游多出来的四件事（见 `bangkok-example.md`）

国内样例（桂林、杭州）**完全覆盖不到**这四类，跑回归时容易漏：

| 类别 | 必须出现的要素 | 常见错法 |
|---|---|---|
| **签证** | 政策名 + 生效日 + 停留上限（如「中泰互免 2024-03-01 生效，单次 ≤30 天 / 180 天累计 ≤90 天」） | 只写「免签」不说停留限制；把「免签」当成「什么都不用办」 |
| **入境登记** | 具体系统名 + 时间窗（如 TDAC，入境前 **72 小时内**） | 漏掉；或写成「提前一周填」——72 小时外填的无效 |
| **汇率** | 数值 + **采集日期** + 换算方向 | 只写「1:5」不带日期，过一个月就变错误信息 |
| **时差** | 小时差 + 对排程的影响（返程航班按哪地时间） | 把时差算进飞行时长，落地时间排错 |

**还有一条专门的知识陷阱**：看到「某某政策优惠」先问「**谁有资格**」。
曼谷「20 泰铢全线票价」搜索结果标题全是这句话，但只限持 13 位泰国身份证的公民，游客实付 BTS 17–65 THB/程。
同类：东南亚国家公园双轨票价、日本 JR Pass 涨价后的适用范围。
